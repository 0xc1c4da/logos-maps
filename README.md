# Maps

A [Logos Basecamp](https://github.com/logos-co/logos-basecamp) app in two modules,
built with [logos-module-builder](https://github.com/logos-co/logos-module-builder):

| Directory | Module | Type | Role |
|---|---|---|---|
| `core/` | `maps_core` | `core` (headless) | The layer registry. Any module can add, update or remove layers and their GeoJSON features through its API and follow its events. Runs under Basecamp or `logosctl` alike. |
| `ui/` | `maps_ui` | `ui_qml` + C++ backend | The map view. Mirrors `maps_core` (depends on it) and renders it with the Logos design system. |

The split is what makes the map programmable: a Basecamp view is not addressable by
other modules, so everything another module should be able to call lives in `maps_core`.
`maps_ui`'s backend is a thin Qt-typed proxy (`modules().maps_core`) that relays the
core's events to the QML replica.

## Module API (`maps_core`)

```
bool        addLayer(layerId, layerJson)      // JSON object; replaces if the id exists
bool        removeLayer(layerId)
bool        setFeatures(layerId, geojson)     // one GeoJSON FeatureCollection
std::string getLayer(layerId)                 // "" if unknown
std::string getFeatures(layerId)
std::string listLayers()                      // [{"id", "layer"}]
int64_t     layerCount()

events:     layerAdded(layerId)  layerChanged(layerId)  layerRemoved(layerId)
```

The core treats layer definitions and features as opaque JSON so the schema is the
callers' to evolve. Suggested layer keys: `title`, `kind` (`markers` | `geojson` |
`tiles`), `style`, `visible`, `zIndex`.

From another module, declare `"dependencies": ["maps_core"]` and call
`modules().maps_core.addLayer(...)` (typed client generated by the builder), or from QML
`logos.callModuleAsync("maps_core", "addLayer", [id, json], cb)`.

## Build

```bash
nix build ./core                                              # result/: plugins/maps_core/...
nix build ./ui --override-input maps_core path:$PWD/core      # the view, against the local core
nix build ./ui                                                # the view, against the published core
```

Nix only sees git-tracked files: `git add` new sources and assets before building.

## Run in Basecamp (development)

```bash
cd ui
nix run . --override-input maps_core path:$PWD/../core          # opens the view + core in Basecamp
nix run .#ui-dev --override-input maps_core path:$PWD/../core   # same, with QML hot reload
```

Inside [logos-workspace](https://github.com/logos-co/logos-workspace) the two modules are
the inputs `maps-core` and `maps-ui`; the override is automatic there:

```bash
ws build --group own
nix run "$LOGOS_WORKSPACE_ROOT#maps-ui--ui-dev" -- --user-dir /tmp/bc-maps
```

Headless, with `logosctl`: install `maps_core`'s `.lgx`, then
`logosctl call maps_core addLayer str:demo 'json:{"title":"Demo"}'`.

## Rules of the road

- Only `bool`, `int64_t`, `std::string` and std containers of them cross the module
  boundary; structured data travels as JSON text. Keep methods and `.rep` slots to
  at most 4 arguments.
- `metadata.json` descriptions: ASCII only, no semicolons (CMake splits on them).
- Render peer-supplied text with `textFormat: Text.PlainText`.
- `maps_core` keeps state in memory for now. Persist through `storage_module`
  before shipping.
